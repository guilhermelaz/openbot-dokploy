Passo 2

Instale no Dokploy

Pré-requisito: VPS com Dokploy instalado (recomendo 8 GB de RAM) e conta no OpenBot (crie pelo app).

  1. No Dokploy, abra o seu projeto → Create Service → Compose. Dê o nome openbot e crie.
  2. Abra a aba Advanced, vá no card Import e cole o texto da aba Base64 em Configuration (Base64).
  3. Clique em Load, confira que apareceu o Docker Compose e o mount seccomp.json, e clique em Import.
  4. Volte na aba General e clique em Deploy. Acompanhe em Logs até o container subir.
  5. Clique em Open Terminal, escolha o container do openbot e rode o comando de login (aba Comandos). Digite o código que chegar no seu e-mail.
  6. Rode openbot status pra conferir que está logado.
  7. Abra o app do OpenBot (desktop, celular ou openbot.run/app) com a mesma conta e selecione o seu servidor.
  8. Conecte os providers (Claude, Codex…) de novo, agora no servidor. O login do seu PC não vale lá.
Não adicione domínio. O OpenBot não publica porta web: o app conecta pelo acesso remoto da própria conta, sem VPN. Deixe a aba Domains vazia.
Prefere fazer manual, sem o Base64?
  1. Crie o serviço Compose, aba General → cole o docker-compose.yml no editor e salve.
  2. Aba Advanced → Volumes → adicione um File Mount com File Path seccomp.json e cole o conteúdo do seccomp.json.
  3. No compose ele vira ../files/seccomp.json, que é o caminho que o template já usa. Depois é só dar Deploy.
Backup e atualização
  1. Backup: na aba Volume Backups, agende o volume openbot-data. Ele guarda os logins dos providers, o banco e a chave de criptografia, então proteja como se fosse senha. Copiar só os arquivos dos agentes não é backup completo.
  2. Atualizar: veja o comando na aba Comandos. Faça backup antes. A atualização pode migrar o banco, e voltar uma versão depois disso não é seguro.
Deu erro? Pegadinhas comuns
  1. Servidor não aparece no app: você rodou o login no container? Instalar não basta. Confira se o app usa o mesmo e-mail.
  2. Erro de sandbox ou user namespace nos logs: confira se o mount seccomp.json existe. Alguns hosts restringem user namespaces ou aplicam regras extras de AppArmor. Veja o troubleshooting oficial no GitHub do OpenBot.
  3. Travando por falta de memória: veja a memória no openbot status, reduza tarefas simultâneas ou aumente a RAM da VPS.

Passo 2

Instale no EasyPanel

Pré-requisito: VPS com EasyPanel instalado (recomendo 8 GB de RAM) e conta no OpenBot (crie pelo app).

  1. No EasyPanel, abra (ou crie) um projeto → + Service → Compose. Dê o nome openbot e crie.
  2. Na aba Source, escolha Git e preencha os 4 campos da aba Source (Git) aqui ao lado: Repository URL, Branch, Build Path e Docker Compose File. Clique em Save.
  3. Na aba Environment, cole as variáveis da aba Environment daqui, ligue Create .env file e salve.
  4. Clique em Deploy e acompanhe em Deployments até o container subir.
  5. Abra o terminal da VPS (SSH ou o terminal do navegador da sua hospedagem) e rode o comando de login da aba Comandos. Digite o código que chegar no seu e-mail.
  6. Rode o comando de status pra conferir que está logado.
  7. Abra o app do OpenBot (desktop, celular ou openbot.run/app) com a mesma conta e selecione o seu servidor.
  8. Conecte os providers (Claude, Codex…) de novo, agora no servidor. O login do seu PC não vale lá.
Não adicione domínio. O OpenBot não publica porta web: o app conecta pelo acesso remoto da própria conta, sem VPN. Deixe a aba Domains vazia.
O compose e o seccomp ficam no repositório público guilhermelaz/openbot-dokploy, na pasta /easypanel. A cada Deploy, o EasyPanel puxa a versão de lá. As suas escolhas ficam só nas variáveis do Environment.
Backup e atualização
  1. Backup: o volume openbot-data guarda os logins dos providers, o banco e a chave de criptografia, então proteja como se fosse senha. Pare o serviço no EasyPanel, copie o volume (veja o comando na aba Comandos) e guarde fora da VPS. Copiar só os arquivos dos agentes não é backup completo.
  2. Atualizar: veja o comando na aba Comandos. Faça backup antes. A atualização pode migrar o banco, e voltar uma versão depois disso não é seguro.
Deu erro? Pegadinhas comuns
  1. As variáveis não pegaram: confira se Create .env file está ligado no Environment e dê Deploy de novo.
  2. Servidor não aparece no app: você rodou o login no container? Instalar não basta. Confira se o app usa o mesmo e-mail.
  3. Erro de sandbox ou user namespace nos logs: confira se o Build Path está como /easypanel, porque o seccomp.json precisa estar ao lado do compose. Alguns hosts restringem user namespaces ou aplicam regras extras de AppArmor. Veja o troubleshooting oficial no GitHub do OpenBot.
  4. Travando por falta de memória: veja a memória no comando de status, reduza tarefas simultâneas ou aumente a RAM da VPS.
